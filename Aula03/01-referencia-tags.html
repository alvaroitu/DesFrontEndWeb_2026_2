1. Estrutura do documento

O esqueleto que se repete em toda pagina. No VS Code, ! + Tab (Emmet) gera tudo isto.

<!DOCTYPE html> nao e tag: e instrucao para o navegador

Codigo 
<!DOCTYPE html>
O que muda

Com DOCTYPE: standards mode — o navegador aplica as regras atuais do padrao.

Sem DOCTYPE: quirks mode — o navegador imita bugs dos anos 1990 e o calculo de largura e altura muda.

Detalhe: primeirissima linha do arquivo, sem nada antes. Nao tem fechamento e nao diferencia maiusculas de minusculas.

<html lang> raiz do documento e idioma do conteudo

Codigo 
<html lang="pt-BR">
  ...
</html>
Para que serve

O atributo lang="pt-BR" diz ao leitor de tela em que idioma pronunciar o texto e liga o corretor ortografico correto do navegador.

<head> e <body> o invisivel e o visivel

Codigo 
<!DOCTYPE html>
<html lang="pt-BR">
<head>
    <meta charset="UTF-8">
    <meta name="viewport"
          content="width=device-width, initial-scale=1.0">
    <title>Minha primeira pagina</title>
    <link rel="stylesheet" href="css/estilo.css">
</head>
<body>

    <h1>Ola, mundo!</h1>
    <p>Este e o conteudo visivel da pagina.</p>

    <script src="js/script.js"></script>
</body>
</html>
Divisao de papeis

<head> — metadados. Titulo da aba, charset, icone, links para CSS e fontes. Nada aparece na tela.

<body> — todo o conteudo que o usuario ve: textos, imagens, listas, tabelas. Scripts no final do body.

Erro de pagina em branco: conteudo escrito dentro do <head> por engano.

2. Dentro do <head>

Pequenos detalhes com grande impacto. Nenhum deles aparece na tela — todos aparecem no resultado.

<meta charset> codificacao de caracteres

Codigo 
<meta charset="UTF-8">
Sintoma quando falta

A palavra informacoes com cedilha e til aparece como informaÃ§Ãµes.

O arquivo tambem precisa estar salvo em UTF-8 — nao basta declarar.

<meta name="viewport"> adapta a pagina ao celular

Codigo 
<meta name="viewport"
      content="width=device-width, initial-scale=1.0">
Sintoma quando falta

No celular o site aparece "miniaturizado", como se fosse a versao de computador reduzida. E a base do design responsivo.

<title> nome do documento

Codigo 
<title>Portfolio de Ana Souza</title>
Onde aparece

Texto da aba do navegador, nome no favorito e titulo azul no resultado do Google. Unico e descritivo por pagina.

<meta name> e <link> descricao, autor, icone e CSS

Codigo 
<meta name="description"
      content="Portfolio de projetos web do aluno X">
<meta name="author" content="Seu Nome">
<link rel="icon" href="img/favicon.ico">
<link rel="stylesheet" href="css/estilo.css">
Para que serve cada um

description — o texto cinza abaixo do titulo no Google.

rel="icon" — o iconezinho da aba.

rel="stylesheet" — liga a folha de estilo. Fora do <head>, o CSS nao e aplicado.

<script> vincula ou embute JavaScript

Codigo 
<script src="js/script.js"></script>
Convencao

No final do <body>, para que o HTML ja esteja carregado quando o script rodar. Mesmo com src, a tag precisa ser fechada.

3. Anatomia da tag, aninhamento e elementos vazios

A gramatica do HTML: como uma tag e formada, em que ordem ela fecha e quais nunca fecham.

Anatomia de uma tag

Codigo 
<a href="contato.html" target="_blank">Fale conosco</a>
 |   |         |               |            |         |
 |   |         |               |            |         +-- fechamento
 |   |         |               |            +-- conteudo
 |   |         |               +-- valor do atributo
 |   |         +-- valor do atributo
 |   +-- nome do atributo
 +-- nome do elemento
Regras

O fechamento repete o nome precedido de barra: </a>.

Atributos so existem na tag de abertura, separados por espaco, com valores entre aspas duplas.

Nomes de tags e atributos em minusculas — boa pratica, nao obrigacao.

Elementos vazios void elements: nao tem conteudo e nao se fecham

Codigo 
<br>      quebra de linha
<hr>      linha divisoria horizontal
<img>     imagem
<input>   campo de formulario
<meta>    metadado no head
<link>    vinculo com arquivo externo

<br />    heranca do XHTML - tambem valida
Por que nao fecham

Nao existe conteudo entre abertura e fechamento: a informacao esta toda nos atributos.

Escrever </br> e erro comum e desnecessario.

Todos os demais exigem fechamento. Esquecer um </div> quebra o layout inteiro — e o navegador nao avisa.

Aninhamento e indentacao quem abre por ultimo fecha primeiro

CERTO

<ul>
    <li><strong>Front-end</strong></li>
    <li>Back-end</li>
</ul>

<p>Texto com <em>enfase</em> no meio.</p>

ERRADO

<ul>
<li><strong>Front-end</li></strong>
<li>Back-end
</ul>

<p>Texto com <em>enfase no meio.</p></em>

No VS Code: Shift+Alt+F formata e indenta o documento inteiro. Indentacao nao muda o resultado no navegador — muda a sua vida.

4. Comentarios e entidades HTML

Escrevendo o que o navegador nao deve interpretar.

<!-- comentario -->

Codigo

  Comentario que ocupa
  varias linhas seguidas

Resultado na tela

Nada. O comentario nao e renderizado.

Mas vai inteiro no codigo-fonte: qualquer visitante le com Ctrl+U. Senha, token e dado de aluno nunca entram em comentario.

5. Atributos globais: id e class

Os dois ganchos que o CSS e o JavaScript vao usar. Hoje eles ainda nao fazem nada visivel.

id e class identidade unica x grupo reutilizavel

Codigo 
<h1 id="titulo-principal">Bem-vindo</h1>

<p class="destaque">Paragrafo importante.</p>
<p class="destaque texto-grande">Duas classes.</p>

<div id="rodape" class="caixa escura">...</div>

<a href="#titulo-principal">Voltar ao topo</a>

<abbr title="HyperText Markup Language">HTML</abbr>
A diferenca que importa

id — um unico elemento na pagina inteira. Serve de ancora: href="#id".

class — repete em quantos elementos quiser; um elemento aceita varias classes.

Outros globais: title, lang, hidden, style e os personalizados data-*.

Passe o mouse: HTML

Valores: minusculas, com hifen e sem acento — caixa-destaque, nunca Caixa Destaque.

6. Titulos: <h1> a <h6>

Hierarquia, nao tamanho de fonte.

<h1> … <h6> o sumario que a pagina desenha sozinha

Codigo 
<h1>Titulo principal da pagina</h1>
    <h2>Secao</h2>
        <h3>Subsecao</h3>
            <h4>Detalhe</h4>

<!-- h5 e h6 existem, mas sao raros -->
Resultado na tela
Titulo principal da pagina
Secao
Subsecao
Detalhe

As regras: um unico <h1> por pagina; nunca pule niveis (de h2 va para h3, nunca direto para h4); o nivel vem do significado, nunca do tamanho da letra. Erro classico: usar <h1> em todos os titulos porque "ficou maior".

O conteudo que sustenta a pagina.

<p>, <br> e <hr>

<p>Segundo paragrafo.</p>

<p>Linha um<br>Linha dois na mesma tag p</p>

Gambiarra a evitar: varios <br> seguidos para "dar espaco" ou <p> vazio como espacador. Espacamento e responsabilidade do CSS.

<strong>, <em>, <b> e <i> significado x aparencia

Codigo 
<p>Texto com <strong>destaque forte</strong>
   e uma <em>enfase</em> no meio da frase.</p>

Texto com destaque forte e uma enfase no meio da frase.

Negrito sem significado e italico sem significado.

Na tela sao identicos. Para o leitor de tela, nao.

Nota: leitores de tela mudam a entonacao em <strong> e <em>. Em <b> e <i> nao mudam nada — e o usuario nao fica sabendo.

11. Imagens: <img>, <figure> e <figcaption>

Peso, acessibilidade e formato.

<img> src e alt sao o par obrigatorio

Codigo 
<img src="img/logo.png" alt="Logotipo do CEUNSP">

<img src="img/campus.jpg"
     alt="Fachada do campus ao entardecer"
     width="600" height="400">
alt e obrigatorio

Descreve a imagem para o leitor de tela e aparece se a imagem nao carregar. Imagem puramente decorativa: alt="".

Formatos: JPG fotos  |  PNG transparencia  |  SVG logos e icones  |  WEBP menor peso.

width e height no HTML evitam que o layout "pule" enquanto a imagem carrega.

Cuidado: nunca use uma foto de 5 MB da camera direto no site — redimensione e comprima antes.

<figure> + <figcaption> liga a legenda ao que ela descreve

Codigo 
<figure>
  <img src="img/grafico.png"
       alt="Grafico de uso de navegadores">
  <figcaption>Fonte: StatCounter, 2026.</figcaption>
</figure>
Resultado na tela

A legenda nao substitui o alt. Sao informacoes diferentes: o alt descreve, a legenda contextualiza.

Nota: <figure> serve tambem para trecho de codigo, grafico e video — nao apenas para imagem.

12. Os nao semanticos: <div> e <span>

Generico nao e sinonimo de errado. A regra: so escolha <div>/<span> depois de procurar uma tag semantica.

<div> e <span> caixa generica de bloco e caixa generica em linha

Codigo 
<!-- CERTO: agrupamento apenas para layout -->
<div class="grade-produtos">
  <article>...</article>
  <article>...</article>
</div>

<!-- CERTO: trecho em linha apenas para estilo -->
<p>Total: <span class="preco">R$ 90,00</span></p>

<!-- ERRADO: ja existe tag propria para isso -->
<div class="titulo">Sobre nos</div>   -->  <h2>
<span class="forte">Cuidado</span>    -->  <strong>
<div class="menu">...</div>           -->  <nav>
Regra de ouro

<div> e bloco; <span> e em linha. Sao o gancho natural do Flexbox e do Grid.

Nao tem significado — e as vezes e exatamente isso que se quer.

Obsoletos, nunca use: <font>, <center>, <big>.

Proporcao: um projeto bem escrito continua tendo <div>. A diferenca esta na quantidade — dezenas em vez de centenas, e sempre por motivo declarado de layout.

NAO SEMANTICO

<div class="alerta">Prazo hoje!</div>
<div class="titulo">Sobre o curso</div>
<span class="negrito">Atencao</span>
<div class="lista">
  <div>Item</div>
</div>

SEMANTICO

<strong>Prazo hoje!</strong>
<h2>Sobre o curso</h2>
<em>Atencao</em>
<ul>
  <li>Item</li>
</ul>

13. Os elementos estruturais do HTML5

Sete tags que descrevem o esqueleto de qualquer pagina. Nenhuma delas muda um pixel — todas mudam o significado.

<header>logotipo, titulo do site, cabecalho da pagina
<nav>menu principal de navegacao
<main>conteudo principal — um so por pagina
<section>bloco tematico, com titulo proprio
<article>faz sentido sozinho: post, noticia, produto
<aside>conteudo relacionado e dispensavel: barra lateral, "veja tambem", publicidade
<footer>contato, creditos, mapa do site

<header>, <nav> e <footer> o que emoldura o conteudo

Codigo 
<header>
  <h1>Portfolio de Ana Souza</h1>
  <p>Desenvolvedora front-end</p>
  <nav>
    <ul>
      <li><a href="index.html">Inicio</a></li>
      <li><a href="projetos.html">Projetos</a></li>
      <li><a href="contato.html">Contato</a></li>
    </ul>
  </nav>
</header>

<footer>
  <p>&copy; 2026 Ana Souza</p>
  <address>ana@exemplo.com.br</address>
</footer>
Quando usar cada um

<header> — cabecalho de um contexto. Pode haver mais de um por pagina.

<nav> — so para blocos principais de navegacao. Nao precisa envolver todo link.

<footer> — rodape do contexto em que esta: creditos, contato, mapa do site.

<header> nao e <head>: <head> guarda metadados invisiveis no topo do arquivo; <header> e conteudo visivel no topo de uma secao. Erro que sempre aparece na correcao: <nav> envolvendo um unico link no meio de um paragrafo.

<main>, <section> e <article> o miolo da pagina

Codigo 
<main>
  <h1>Blog da turma</h1>

  <section>
    <h2>Ultimos posts</h2>

    <article>
      <h3>Semantica em HTML5</h3>
      <p>Publicado em
         <time datetime="2026-08-26">26/08/2026</time></p>
      <p>Texto completo do post...</p>
    </article>

    <article>
      <h3>Flexbox na pratica</h3>
      <p>Outro post independente...</p>
    </article>
  </section>
</main>
Quando usar cada um

<main> — conteudo principal e unico da pagina. Fora dele: header, nav, aside, footer.

<section> — bloco tematico. Exige titulo proprio (h2, h3...).

<article> — faz sentido sozinho, fora da pagina: post, noticia, comentario, produto.

Teste do feed: se o trecho pudesse ser publicado isolado, compartilhado por link proprio ou aparecer num RSS sem perder sentido, e <article>. Caso contrario, e <section>.

Sinal de alerta: <section> sem titulo e o indicio mais confiavel de que ali cabia um <div>.

<aside>, <time> e <address>

Codigo 
<aside>
  <h2>Veja tambem</h2>
  <ul>
    <li><a href="#">Acessibilidade na web</a></li>
  </ul>
</aside>

<p>Inscricoes ate
   <time datetime="2026-04-30">30 de abril</time>.</p>

<address>
  <a href="mailto:ana@exemplo.com">ana@exemplo.com</a>
</address>
Quando usar cada um

<aside> — relacionado, porem dispensavel. Nao e sinonimo de "coluna da direita".

<time> — datetime em ISO (AAAA-MM-DD); o texto visivel pode ser livre.

<address> — contato do autor ou do site. Nao serve para qualquer endereco postal citado no meio do texto.

Resultado na tela: inscricoes ate 30 de abril.

ana@exemplo.com — o navegador exibe em italico por padrao.

section, article ou div? tres perguntas que resolvem quase todos os casos

1. Este trecho faria sentido publicado sozinho, fora da pagina?
SIM → <article>    NAO → siga para a 2

2. Este trecho tem tema proprio, com um titulo que voce conseguiria escrever?
SIM → <section>    NAO → siga para a 3

3. O agrupamento existe apenas para posicionar ou estilizar com CSS?
SIM → <div>    NAO → reveja: talvez seja header, nav, aside ou footer

Nenhuma das tres? Provavelmente aquele trecho nao precisa de container nenhum.

15. Semantica interativa: nativo antes de JavaScript

Comportamento pronto, acessivel, sem uma linha de script.

<details> + <summary> FAQ que abre e fecha sozinho

Codigo 
<details>
  <summary>O que e semantica em HTML?</summary>
  <p>E o uso de tags cujo nome descreve o conteudo.</p>
</details>
Resultado na tela — clique e depois navegue com Tab
O que e semantica em HTML?

E o uso de tags cujo nome descreve o conteudo.

Acessivel por teclado de fabrica. Zero JavaScript.

<progress> e <meter>

Codigo 
<progress value="7" max="12">7 de 12 aulas</progress>

<meter value="0.8" min="0" max="1">80%</meter>
Resultado na tela

7 de 12 aulas   progress: tarefa em andamento

80%   meter: medida dentro de uma faixa

<button> x <a> x <div onclick>

Codigo 
<button type="button">Executa uma acao</button>
<a href="pagina.html">Leva para outro lugar</a>

<!-- ERRADO -->
<div onclick="fazAlgo()">Parece um botao</div>
Teste com a tecla Tab

  Leva para outro lugar

<a> navega  |  <button> age  |  <div onclick> nao recebe foco pelo teclado e nao responde a Enter e Espaco.

Regra: todo elemento nativo ja vem com foco, navegacao por teclado e anuncio corretos. Recriar isso com <div> custa mais codigo e quase sempre sai pior.

16. Landmarks: acessibilidade sem esforco extra

Cada elemento estrutural ja e um ponto de navegacao para o leitor de tela.

Landmark implicito de cada elemento HTML5
Elemento HTML5Landmark implicitoO leitor de tela anuncia
<header>banner"banner"
<nav>navigation"navegacao"
<main>main"principal"
<aside>complementary"complementar"
<footer>contentinfo"informacoes do conteudo"
<form>form"formulario"
<section>region (com titulo)"regiao + titulo da secao"
<article>article"artigo"

Consequencias praticas

  • Escrever <div role="navigation"> faz o mesmo que <nav> — com mais codigo e mais chance de erro.
  • Primeira regra do ARIA: nao use ARIA se existe um elemento HTML nativo que ja faz aquilo.
  • <header> e <footer> so valem como landmark quando estao no nivel do <body>.
